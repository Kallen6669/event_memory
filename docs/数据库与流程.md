# 数据库与流程

程序使用Python自带SQLite，分为业务库和调用账本。每个交付入口显式指定两份数据库，避免不同运行混用请求状态。

2026-10-29评审第1—5项修复后，业务库版本5，共16张实体表：

| 表 | 用途 |
| --- | --- |
| accounts | 本地账号、授权状态与代次 |
| tombstones | 已清除录音的防复活标记 |
| sources | 来源文档、版本与完整原文 |
| segments | 原文片段的时间、说话人和字符定位 |
| jobs | 处理作业、配置和进度 |
| batch_results | 已提交批次检查点 |
| events | 事件、主张、引用、关系与质量标记 |
| unclassified | 未归类片段与原因 |
| topics | 主题 |
| associations | 事件与主题的多对多关联 |
| corrections | 人工主题纠正历史 |
| selections | 固定范围选择与版本快照 |
| batch_inputs | 首次批次阅读上下文，恢复时保持原请求 |
| input_dependencies | 实际输入候选的来源、版本与账号代次依赖 |
| content_purges | 跨库清除任务，重启后继续清理调用副本 |
| operation_receipts | 主题纠正及固定选择的幂等回执和结果核对 |

具体字段以`event_memory/store.py`的SCHEMA为准，升级兼容逻辑见`migrations.py`。

主关系：一个来源有多个原文片段和作业，一个作业有多个批次、事件及未归类片段；事件和主题为多对多；纠正记录作用于事件主题关联；固定选择保存选定事件版本与证据范围。主张、关系和质量标记等变长内容使用JSON字段随事件读取。原文只在来源中保存，片段通过字符范围定位，查询时回读。

调用账本：`ledger_meta`保存账本元信息，`model_calls`保存逻辑请求、原始响应、用量、状态和尝试历史。完整响应才能提交候选；未知请求不自动重发。账本不是可随意删除的缓存。

解析→分批→候选召回及精简上下文→大模型生成→程序校验→必要时模型修正→保存事件、主题与检查点→本机查询。生成和修正调用模型；普通查看、查询、回读、主题纠正和导出由本地程序完成。

事件对应可回读的情景记忆；主题用于组织和查找，不把同主题事件自动合并成一段失去原始时间的总结。跨批延续与新录音都保留各自来源和依据。Jev当前暂未接入。
