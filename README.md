# 离线ASR事件与主题记忆

将带时间、说话人的ASR转录整理成可以查询、回读原文、纠正主题和固定选择导出的事件记忆。当前为Windows本机部署，不需要单独安装数据库服务。

本项目提供两种使用方式：**直接查看最新结果**和**从原始文档完整重新处理**。GitHub只包含代码、配置示例与说明；私下交付的压缩包另外包含真实转录、固定GT、最新结果、报告和经所有者授权提供的账户凭据。源码仓库本身不含这些私有内容。

## 快速开始

使用Windows、Python 3.10或以上版本，安装Python时勾选加入PATH。将整个压缩包解压到普通文件夹，不要在压缩软件预览窗口中运行。

首次启动会在项目中创建`.venv`并安装依赖，需要联网访问Python软件包源。已有依赖时不重新安装。所有页面只监听`127.0.0.1`，不提供公网部署或多用户登录。

### 方式一：直接查看已有结果

双击根目录的`start-view.cmd`，浏览器会打开`http://127.0.0.1:8765/`。关闭服务用Ctrl+C。

此入口不调用模型，不需要登录账户。可以查询事件和主题、查看概括与主张、回读证据原文，试用主题纠正和固定选择导出。

首次启动会把`delivery_data/results/`中的两份数据库备份到`.runtime/handoff-view/`，页面操作只作用于这份工作副本，交付原件不变。再次启动保留这份工作副本及你的页面操作。注意：页面仍有生成入口，手动触发生成或追加复核会需要授权和消耗用量；单纯浏览不会。

若8765端口已占用，可以在命令提示符中执行：

```bat
start-view.cmd --port 8770
```

只检查私有结果是否可读取，不开页面也不调用模型：

```bat
scripts\bootstrap.cmd view --check
```

从GitHub下载代码后，需把私下收到的`delivery_data`文件夹放进项目根目录，才能使用本方式。仅有源码不会自动下载真实数据。

### 方式二：从ASR完整重新处理

双击`start-run.cmd`。默认读取`delivery_data/input/TRANSCRIPT.md`，使用当前模型和精简上下文策略，从独立空库执行完整处理；控制台显示批次进度，完成后自动打开新结果页面。

```text
ASR原文
→ 解析时间、说话人和原文定位
→ 构建阅读批次及有限历史上下文
→ 大模型生成事件、主张、主题及候选关联
→ 程序核验逐字引文、引用范围、条件与否定等
→ 必要时要求大模型修正（有次数上限）
→ 提交批次、保存检查点
→ 查询主题/事件、回读原文、纠正及导出
```

大模型主要用于候选生成和被拒结果的修正；解析、候选召回、上下文构建、程序校验、保存和普通查询不调用模型。Jev暂未接入。

重新处理会使用已授权账户的套餐用量，不是离线推理。本轮相同原文实测43批，约32分钟；服务速度、网络、修正次数和额度会影响耗时。

处理另一份UTF-8转录：

```bat
start-run.cmd --input "D:\材料\新转录.md" --port 8771
```

新运行保存在`.runtime/handoff-runs/时间戳/`，包含独立业务库、调用账本、输入副本、事件JSON、工程报告和用量统计。`current.json`记录最近运行。已有未完成运行时，再次执行使用同一输入恢复；不会绕过未知请求重新计次。已经完成后再次启动本入口，会新建完整运行并再次消耗用量。不要同时启动两个复跑窗口。

网络中断后缺少模型完整终态的请求仍保留为未知，不自动重发。不要删除`current.json`或账本来跳过未知状态；核对后再决定恢复。普通未完成批次沿原作业身份恢复，不重跑已提交批次。

## 账户凭据与重新登录

当前模型为`gpt-6.1-sol`，通过本应用自己的ChatGPT授权调用；没有恢复DS调用，没有提供DS API Key。

按交付者明确要求，**私有压缩包包含`private_credentials/transfer.json`，其中是可转移的账户访问及续期凭据（明文），不是普通API Key**。它和真实数据只供私下交接，不要提交GitHub或公开分享。使用它的调用计入交付者账户的套餐用量。

首次运行方式二时，脚本仅在目标机尚无本应用凭据的情况下导入，将其用当前Windows用户的DPAPI重新加密到`.runtime/openai-probe/credentials.dpapi`。已有本机凭据优先，不覆盖。原Windows加密文件直接复制无法跨用户使用，因此采用显式转移文件导入。

账户权限、授权有效期和续期是否仍可用以服务端为准，不能保证永久可用。续期令牌会旋转；移交后应由一台机器使用该授权，交付者不要继续用旧凭据并发续期。同一转移包也不能当成长期多机共享密钥。完成导入后可从目标机删除`private_credentials/transfer.json`，解压包和压缩包中的副本也需自行管理。

如果交付凭据已失效，或负责人希望使用自己的账户，在项目目录依次执行：

```bat
.venv\Scripts\python -X utf8 -m event_memory.chatgpt_auth login
.venv\Scripts\python -X utf8 -m event_memory.chatgpt_auth probe
```

第一条命令会等待本人在官方页面授权；等待期间打开`.runtime/openai-probe/authorization-url.txt`里的地址。第二条发送一次最小推理以核验权限。完成后重新执行`start-run.cmd`。不要把授权地址、回调参数或凭据贴到日志/聊天中。当前实现的凭据存储只支持Windows。

## 最新结果与评测范围

| 项目 | 最新结果 |
| --- | --- |
| 全文批次 | 43/43完成 |
| 原文片段 | 2764 |
| 事件／主张／主题 | 31／491／31 |
| 未归类片段 | 87 |
| 作业耗时 | 32分13秒 |
| 模型完整响应／未知请求 | 53／0 |
| 已知输入／输出token | 398205／106039 |
| 固定GT核心有据支持 | 85/86，1项指代待判 |

优化前历史作业90分11秒，本轮32分13秒；完整响应等待累计66分23秒降至32分10秒，总已知输入token减少39.4%。历史作业包含修复、授权和暂停，因此不能把全部提速归因于代码，也不承诺下一次精确复现耗时。

固定GT核心覆盖持平；GT之外发现两处新版表述风险：人物关系过度具体化，以及省略原文“可能”。整体语义精确率未计算，不能称为100%准确。GT是开发材料的AI辅助参考，不是独立人工盲测。事件数量允许合理拆并；模型再次运行的文字、数量和主题不保证完全相同。

先看`delivery_data/reports/report.md`，再看`semantic-review.md`和`GT逐项对比.csv`。固定GT位于`delivery_data/input/gt.json`，只用于核对，不进入处理模型的输入。复跑产生工程报告，**不会自动完成新的语义GT判分**；负责人需要按固定检查点比对新结果和原文。

旧结果不混入默认演示。历史比较的必要摘要和重核说明位于`delivery_data/reports/`，未打包开发者本地测试目录、恢复脚本、失败实验、虚拟环境或旧数据库。

## 文件与数据库

```text
event_memory/               后端、提示词、解析、校验、存储和前端资源
scripts/handoff.py          两种交付入口，明确绑定业务库与账本
scripts/bootstrap.cmd       Python环境准备
start-view.cmd              查看最新结果
start-run.cmd               完整重新处理
pyproject.toml              依赖与包配置
.env.example               配置示例，无凭据
docs/                      流程图与数据库说明
delivery_data/input/       私有原文、固定GT
delivery_data/results/     最新业务库、账本、事件快照
delivery_data/reports/     最新报告及必要历史比较摘要
private_credentials/      私下交接凭据，首次复跑时导入
.runtime/                  启动后生成的工作副本和复跑数据
```

SQLite由Python自带，数据在表中，不需要把数据库导入PostgreSQL。业务库12张实体表、调用账本2张实体表；兼容视图不重复保存数据。人物主张等可变列表使用表字段中的JSON，不是独立JSON数据库。详细关系见`docs/数据库与流程.md`。

## GitHub与交付包的区别

GitHub地址：https://github.com/Kallen6669/event_memory 。仓库保留可部署源代码、启动脚本、说明、流程图和配置示例；不上传真实原文、GT、结果数据库、模型响应、任何凭据或本地测试文件。

私有压缩包与GitHub使用同一套程序代码，另外提供结果和凭据。`release-manifest.json`记录对应代码提交及文件哈希，`delivery-verification.json`记录打包时的离线检查。整个文件夹可直接交付，不需要开发者原来的绝对路径。

原开发数据库没有被替换或清空。查看模式和复跑模式的修改都限于交付目录自己的运行数据。
